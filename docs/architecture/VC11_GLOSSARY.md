## 1. General System & Architecture Terms

### VC11
The internal project code name for the **Gmail AI Dashboard & Inbox Assistant**, an enterprise-grade personal intelligence hub that connects to Gmail, synchronizes email data into PostgreSQL, classifies messages using LLMs, and provides grounded question-answering with Human-in-the-Loop email composition.

### Central Application Database (App DB)
The primary PostgreSQL instance hosted alongside the production application (e.g. on Heroku), storing shared system state, user identities, OAuth credentials, and synchronized mailboxes for users who have not attached a personal database.

### Personal Database (User DB)
A private PostgreSQL instance supplied by a user via the Developer Settings panel (`developer_database_url`). When configured, all new syncs, vector embeddings, classifications, and chat histories are routed strictly to this database, isolating user data from the central application database.

### Strict Failure Mode
The deliberate design rule in VC11 stating that if a user's configured Personal Database connection fails (due to network timeout, authentication error, or server shutdown), the system **never silently falls back** to the Application Database. It remains locked to the Personal Database mode and surfaces an error to protect data boundaries.

### ContextVar Routing
The Python `contextvars` mechanism (`database_url_context` and `llm_key_context`) used by VC11 middleware to bind personal database URLs and custom API keys to the asynchronous request context, allowing seamless per-request database swapping without thread-safety conflicts.

## 2. Database & Persistence Terminology

### Alembic
The database migration tool for SQLAlchemy. In VC11, all schema changes are managed strictly via 16 numbered migration scripts in `backend/alembic/versions/` (e.g. `20261012_0001_rebuild_gmail_dashboard_schema.py` through `20261030_0016_developer_settings.py`). Direct SQL initialization via `schema.sql` is deprecated.

### `pgvector`
An open-source PostgreSQL extension that enables vector similarity search directly within SQL queries. VC11 uses pgvector as its sole vector storage engine.

### `HALFVEC(3072)`
A 16-bit half-precision floating-point vector data type provided by pgvector. VC11 uses `HALFVEC(3072)` in the `email_embeddings` table to store Azure OpenAI `text-embedding-3-large` embeddings, reducing vector storage footprint by 50% while maintaining cosine similarity ranking accuracy.

### Cosine Distance (`<=>`)
The pgvector SQL operator used to calculate the cosine distance between two vectors:
$$\text{distance} = 1 - \cos(\theta) = 1 - \frac{\vec{u} \cdot \vec{v}}{\|\vec{u}\| \|\vec{v}\|}$$
Lower distance indicates higher semantic similarity.

### `email_chunks`
The relational table storing semantic text fragments of synchronized emails generated by recursive character splitting, along with offset indices and SHA-256 content hashes.

### `email_embeddings`
The relational table storing dense 3072-dimensional vector representations of email chunks alongside denormalized metadata (subject, sender, recipients, timestamps, and `metadata_json`).

### `chat_sessions`
The relational table representing a distinct conversational thread between a user and the AI Inbox Assistant.

### `chat_messages`
Individual user prompts and assistant responses within a `chat_session`, identified by role (`user`, `assistant`, `system`).

### `chat_retrievals`
The audit log table recording the exact email chunks retrieved, their similarity scores, and their ranking order for every AI assistant message generated.

### `email_send_approvals`
The approval queue table storing email drafts composed by the AI assistant that require explicit human approval before being transmitted via the Gmail API.

## 3. AI, RAG & Vector Search Terminology

### RAG (Retrieval-Augmented Generation)
An AI architecture that grounds large language model responses in factual context retrieved from private data stores (the user's emails) rather than relying solely on the model's pre-trained knowledge.

### Grounded Answer
An AI response that explicitly cites retrieved evidence using numbered brackets (e.g., `[1]`, `[2]`), allowing the user to inspect the source email and verify that the model did not hallucinate facts.

### Recursive Character Chunking
The text splitting algorithm (`RecursiveCharacterTextSplitter`) that divides an email body into 1,000-character segments with 150-character overlaps, respecting paragraph and sentence boundaries.

### Sparse vs. Dense Retrieval
- **Dense Retrieval:** Vector similarity search using mathematical embeddings that capture semantic intent and synonyms.
- **Sparse Retrieval:** Exact lexical keyword matching using BM25, scoring documents based on term frequency and inverse document frequency.

### Reciprocal Rank Fusion (RRF)
An algorithmic technique used by VC11's `GmailHybridRetriever` to merge rankings from dense vector search and sparse BM25 keyword search:
$$RRF(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$
where $k$ is a smoothing constant (typically 60) and $r_m(d)$ is the rank of document $d$ in retrieval system $m$.

### Multi-Query Expansion
A technique implemented in `ConditionalMultiQueryRetriever` where the LLM rewrites a complex user query into 3 complementary search variants to maximize recall across diverse phrasing.

### Contextual Compression
The process of filtering, deduplicating, and condensing retrieved email chunks to fit within LLM context token limits without losing essential factual details.

## 4. Agentic Patterns & LangGraph Terminology

### LangGraph
A library for building stateful, multi-actor agent applications using directed graph workflows. VC11 uses LangGraph's `StateGraph` in `app/rag/graph_agent.py` to coordinate the mailbox assistant.

### `MailboxState`
The `TypedDict` tracking the state of an assistant execution turn:
```python
class MailboxState(TypedDict, total=False):
    query: str
    effective_query: str
    intent: str
    messages: list[Any]
    answer: str
    iterations: int
    steps: list[dict[str, Any]]
    approval_id: str | None
    plan: list[str]
    evidence_validated: bool
```

### Checkpointer (`SqliteSaver` / `PostgresSaver`)
The LangGraph persistence mechanism that serializes graph execution state after every node transition, enabling session resumption, state history inspection, and debugging.

### ReAct (Reasoning and Acting)
An agent design pattern where the model alternates between generating explicit thoughts, selecting actions (tool calls), observing tool outputs, and generating answers.

### Router Pattern
The initial decision node in VC11's agent workflow (`ROUTER_PROMPT`) that inspects the user's input and classifies it into one of 7 distinct intent paths: `RAG_QUERY`, `ACTION_DRAFT`, `ACTION_SEND`, `ACTION_SCHEDULE`, `PLAN_AND_EXECUTE`, `SUMMARIZE`, or `GENERAL_CHAT`.

### Plan-and-Execute Pattern
A multi-step pattern where the LLM decomposes complex queries (e.g. *"Find all bills from October, calculate the total, and draft an expense summary"*) into a discrete sequential plan of 2–4 tasks executed in order.

### Human-in-the-Loop (HITL)
A safety pattern ensuring that autonomous agents cannot execute irreversible or external actions (such as sending emails or modifying accounts) without explicit user confirmation through the user interface.

## 5. Model Context Protocol (MCP) Terminology

### Model Context Protocol (MCP)
An open standard developed by Anthropic that standardizes how AI applications expose tools and data sources to models over standard input/output (stdio) or HTTP/SSE transports.

### Gmail MCP Server
VC11's implementation in `app/services/gmail_mcp_server.py` that exposes the user's Gmail mailbox as a standardized MCP tool (`search_mailbox`) using the authenticated user's OAuth tokens.

### Read-Only MCP Tool
VC11's MCP server is strictly read-only. It exposes search and read tools (`gmail.readonly`) but intentionally does not expose write, delete, or send tools via the MCP protocol.

### In-Process vs. Subprocess Transport
While standard MCP operates over spawned subprocesses communicating via JSON-RPC stdio pipes, VC11 provides an in-process Python callable bridge (`app/rag/gmail_mcp.py`) that executes MCP-compliant tool routines directly within the ASGI worker context for lower latency.

## 6. Gmail API & OAuth Terminology

### Google OAuth 2.0
The authorization framework used by VC11 to obtain delegated access to user Gmail mailboxes. Scopes requested include `openid`, `userinfo.email`, `userinfo.profile`, `https://www.googleapis.com/auth/gmail.readonly`, and `https://www.googleapis.com/auth/gmail.send`.

### PKCE (Proof Key for Code Exchange)
An OAuth 2.0 security extension implemented via `code_verifier` and `code_challenge` cookies to prevent authorization code interception attacks.

### Incremental Synchronization
The process of fetching only new or modified emails since the previous sync by utilizing Gmail's `historyId` cursor rather than re-downloading the entire mailbox.

### Sync Heartbeat Lease
A concurrency control lock stored in `gmail_accounts.inbox_sync_heartbeat_at` with a 15-minute lease time, preventing multiple concurrent background threads from attempting to synchronize the same mailbox simultaneously.

## 7. Frontend & UI Terminology

### Server-Sent Events (SSE)
A unidirectional HTTP streaming protocol (`text/event-stream`) allowing the FastAPI backend to push real-time updates to the React frontend. VC11 uses SSE for sync progress (`/api/gmail/sync/stream`) and AI agent activity telemetry (`/api/rag/chat/stream`).

### `SearchActivity`
The frontend telemetry UI component (`components/SearchActivity.jsx`) that renders a live stopwatch, progress bar, and step-by-step observable tool executions received over the SSE stream.

### DOMPurify
The client-side XSS sanitization library used in VC11 to sanitize HTML email bodies before injecting them into the DOM via `dangerouslySetInnerHTML`.

### Citation Badge (`[1]`, `[2]`)
Clickable pill buttons rendered inline within AI answers that link directly to cited source emails and open the `EmailDetailsModal`.

### ComposeModal
The floating, dockable, minimizable email composition window in the React frontend.

## 8. Security & Infrastructure Terminology

### SSRF (Server-Side Request Forgery)
An attack where an attacker induces a server to make network requests to an arbitrary destination. VC11 prevents SSRF on personal database URLs by DNS-resolving hostnames, blocking private IP ranges, and pinning the IP address via `hostaddr`.

### DNS Rebinding Protection
A security mitigation implemented in `get_pinned_hostaddr` where hostnames are resolved to IP addresses at validation time and pinned during connection establishment, preventing attackers from switching DNS records between check and connection.

### Fernet Encryption
A symmetric encryption recipe built on 128-bit AES in CBC mode with HMAC-SHA256 authentication. VC11 uses Fernet to encrypt developer database URLs and custom LLM keys at rest.

### `ChatConcurrencyLock` & `ChatRequestLease`
Database tables and row-level locks that enforce hard concurrency limits (maximum 5 concurrent requests) and prevent resource exhaustion.
